# 主布局需求

## Header 布局调整

- Header 高度固定为 56px，位于侧栏右侧并与侧栏顶部 Logo 区域等高。
- 面包屑导航移动到 Header 左侧，距离左侧 24px，按当前路由显示并保留原有跳转与自定义路径能力。
- Header 右侧依次展示帮助中心、消息中心和用户头像；帮助与消息仅通过图标和 Tooltip 展示，入口暂时禁用。
- 侧栏底部用户信息模块移除，用户名称、角色、上传任务和退出登录下拉菜单统一由 Header 用户头像承载。

## 用户菜单

- 用户弹出菜单顶部展示“个人中心”和“账号设置”入口。
- 两个入口点击后提示“功能正在建设中，即将开放”，暂不跳转。
- “退出登录”与其他菜单项之间使用横向分隔线区分。

## 功能目标

为管理平台业务页面提供统一的头部、左侧菜单和中间路由内容区域，并与登录、404 等全屏页面分离。

## 路由分类

- 全屏布局：登录、404 等无需管理平台导航框架的页面，作为顶层路由配置。
- 主布局：其他业务页面统一作为主布局路由的子路由配置。
- 路由通过 `meta.layout` 明确标记布局类型，取值为 `fullscreen` 或 `main`。

## 布局结构

- 顶部展示平台通用信息和平台名称。
- 左侧展示业务菜单，并支持折叠。
- 中间区域通过 `RouterView` 展示当前业务页面。
- Header 用户区域在存在未完成上传任务时展示红色数量徽标，并在用户下拉菜单提供上传任务入口；无任务时隐藏入口。
- 上传任务入口打开全局任务进度弹窗，展示进度以及暂停、继续、重试、重新选择原文件和取消操作。
- 主布局占满浏览器可视区域。

## 菜单规则

- 菜单项从主布局下配置了 `meta.menu` 的业务子路由生成。
- 菜单名称从路由的 `meta.titleKey` 读取国际化文案。
- 点击菜单项进入对应业务路由，并根据当前路由保持选中状态。
- 尚无业务路由时允许菜单为空，不创建虚构业务菜单。

## 面包屑规则

- 主布局内容区在业务页面之前统一显示面包屑，全屏路由不显示。
- 路由变化时保存变化前的完整路径列表，并根据 `route.matched` 生成新的完整默认路径列表。
- 路径标题优先使用动态 `meta.title`；不存在时读取 `meta.titleKey` 对应的国际化文案，没有标题的匹配记录不生成路径项。
- 当前路径项仅展示标题，非当前路径项可以通过对应路由地址导航。
- 主布局通过具名 injection key 提供 `addPath(callback)`，供子页面定制完整路径列表。
- `callback` 接收当前 `route`、`oldPathList` 和 `newPathList`，并返回用于整体替换的完整路径列表；返回空数组时清空面包屑。
- 回调接收的旧、新列表均为快照，调用方不得通过原地修改入参改变布局状态。

## 主题与适配

- 使用 Ant Design Vue Layout 和 Menu 组件。
- 支持浅色、深色及后续扩展主题，不硬编码与主题冲突的颜色。
- 主布局菜单跟随全局实际主题，在浅色模式下使用浅色菜单，在深色模式下使用深色菜单。
- 使用项目已有 rem 和通用工具类约定。

## 接口依赖

当前无后端接口依赖，后续可根据权限与动态菜单协议调整菜单来源。

- 面包屑不新增后端接口、第三方依赖或全局状态。

## 验收标准

- 404 页面保持全屏展示，不出现头部和左侧菜单。
- 根路径及后续业务路由使用主布局。
- 主布局包含头部、左侧菜单和中间路由出口。
- 菜单能够根据路由配置生成、跳转并同步选中状态。
- 主布局路由变化后面包屑整体更新，并保留变化前的完整路径列表供 `addPath` 回调读取。
- 动态路由标题优先于默认国际化标题，面包屑使用稳定路由地址作为渲染标识。
- 子页面能够通过注入的 `addPath(callback)` 返回完整列表替换当前面包屑。
- 面包屑路径列表使用 `sessionStorage` 缓存；刷新页面时若缓存包含当前路由，则截取至当前路径恢复。
- 当前路由不在缓存中或缓存数据无效时，回退为当前路由生成的默认面包屑；路径列表变化后同步更新缓存。
- 页面通过格式化、ESLint、TypeScript 检查和生产构建。

# 布局调整补充

主布局不再渲染独立头部；用户信息、上传任务和退出登录入口固定在左侧菜单底部，菜单内容超出可视区域时仅菜单区域滚动。
