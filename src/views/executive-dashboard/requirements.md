# 数据总览需求

## 功能目标与使用场景

管理员按项目范围、标注类型和周期查看商户经营、数据生产、项目运行和风险指标。所有账号均使用接口数据，删除账号白名单和静态模拟指标。

## 字段与展示内容

- 经营概览：项目总数、进行中项目、数据总量、已完成数据、整体完成率和模型标注占比。
- SALT：人工节省率、周期缩短率、模型达标项目率；直接展示接口百分比字符串，不再次乘以 100。
- 生产构成：人工、模型标注框总量与二者来源占比。接口未提供待完成框数，取消原模拟剩余量和三段生产进度，禁止与经营概览的样本数量混算。
- 生产趋势：直接使用接口日期及人工/模型标注框数量绘制堆叠柱状图，不补造日期或重算时间桶。
- 项目运行：正常、关注、风险项目数；状态和进度分布使用接口 code、label、count、percentage。状态包含系统处理中、进行中、已完成、失败；进度为后端给出的五档计划达成率区间。环形中心为状态数量合计，图例保留零值，零合计展示空图表。
- 风险待办：风险、超期、即将到期、长期未收敛项目数量。

## 交互规则

- 默认全部项目、全部标注类型、7天，首次进入自动请求数据。
- 指定项目展示多选下拉，复用项目列表接口并支持名称远程搜索；切换到指定项目或清空选择时，使用黄色 `message.warning` 提示选择，不显示常驻提示条、不按全部项目查询；未选项目时点击刷新再次提示，同一消息不堆叠。
- 标注类型复用已启用标注类型 Store；首位为默认选中的“全部类型”，选项值为空字符串，请求时省略 annotationTypeId；选择具体类型时发送真实 ID。
- 项目多选框宽度为 210px，保留一个已选标签并截断长名称，省略数量标签与已选标签保持同一行。
- 统计周期沿用“7天、30天、3个月、6个月、1年”文案，对应接口 period 枚举的映射保持不变。
- 筛选变化自动刷新，刷新按钮重新请求当前条件，加载期间禁止重复刷新。
- 趋势按日/周/月传 window=DAY/WEEK/MONTH，切换仅更新趋势接口。
- 快速切换以最新请求为准，旧响应不得覆盖新筛选结果；卸载后停止更新状态。

## 状态处理

- 首次加载及筛选变化时清除旧结果，展示 loading 与缺失占位，不用零值模拟未返回的指标。
- 先校验业务 code（字符串或数值 0），失败依次采用业务 message、外层 message、模块通用错误提示。
- 成功响应 data 缺失或结构错误时进入错误状态；缺失指标展示占位，缺失或空集合显示空图表。
- 主指标失败展示页面错误并可刷新重试；趋势独立展示加载和失败状态。

## 接口依赖

依据 `docs/apiList/商户数据总览.json`，在 `src/api/executive-dashboard.ts` 封装以下 GET 接口：

| 路径                                    | 用途                   |
| --------------------------------------- | ---------------------- |
| `/executive-dashboard`                  | 经营六项指标           |
| `/executive-dashboard/production`       | SALT 和两类框数量      |
| `/executive-dashboard/production/trend` | 趋势日期与框数量序列   |
| `/executive-dashboard/projects`         | 健康度、状态与进度分布 |
| `/executive-dashboard/risks`            | 风险四项指标           |

公共参数为 projectCodes（项目 code 数组）、period、annotationTypeId，趋势另传 window。数组按 OpenAPI 默认 form/explode 发送重复 query key。全部项目和全部类型不传 UI 哨兵值。鉴权复用 HTTP 层，不使用文档示例凭证。项目选项复用 `/projects`，标注类型复用 `/annotation-types/page`。

## 验收标准

- 五个接口驱动所有卡片和图表，生产代码无白名单和静态 mock 指标。
- 筛选、刷新、趋势窗口传参符合文档，快速切换不会显示旧结果。
- 空值、业务失败和网络异常不导致崩溃，也不伪装成全零统计。
- 复用 DmCharts、格式化工具和 Ant Design Vue，保留现有卡片布局和主题能力。
- API 映射、参数、错误处理及加载竞态经过针对性测试，运行格式、ESLint、类型和构建检查。
