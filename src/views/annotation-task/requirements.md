# 标注任务页面需求

## 功能目标

提供标注任务列表、详情、样本分页、规则校验记录、人工质检记录和提交质检入口，并为工作台标签配置、重新指派保留最新接口边界。

## 页面职责

- 列表页负责聚合状态统计、表格状态筛选、搜索、排序、分页和详情跳转。
- 顶部状态统计卡片不显示边框，数字使用与列表样本数量一致的默认界面字体和数字样式。
- 统计卡片内的标签和数字整体垂直居中，与项目管理页面保持一致。
- 统计卡片文字左侧展示与任务状态匹配的蓝色图标，图标置于浅蓝色圆形底中。
- 统计卡片统一使用项目管理页面的 8px 圆角、12px 卡片间距和 108px 高度；列表容器使用 20px 内边距且不额外增加边框。
- 任务列表容器的标题和表格上、左内边距与项目管理列表保持一致，统一使用 20px。
- 详情页负责展示任务信息、样本、规则校验记录和人工质检记录，并通过 API 触发工作台及提交质检；标签配置仅供工作台使用。
- 标注内容、质检填写和最终提交由工作台完成，管理端不提供编辑表单。
- 详情使用独立路由 `/annotation-task/:id`，不作为列表页子路由且不生成侧边菜单项。
- 规则校验记录与人工质检记录在宽屏下分两列展示；两张记录卡片分别根据自身内容自适应高度，不因同一行另一张卡片的内容高度被拉伸。窄屏改为单列后仍保持各自内容高度。

## 验收标准

- 样本默认 30 条/页，样本列表使用响应式多列卡片（大屏 6 列、中屏 4 列、小屏 3/2 列、窄屏 1 列）；样本点击可进入当前任务及样本 ID 对应的工作台定位。
- 样本卡片展示样本序号、样本名称和修改建议状态（无需修改、必须修改、建议修改）；必须修改为红色、建议修改为黄色并显示右上角感叹号，问题等级样式优先于样本状态。无问题且接口 `itemStatus` 为 `ANNOTATING` 或 `COMPLETED` 时卡片显示绿色并在右上角显示对号；其他无问题状态使用白底灰边。当前接口未提供最后修改时间，因此不展示该字段。
- 样本卡片统一承载问题等级、悬浮详情和工作台跳转，可在样本列表与规则命中样本中复用。
- 悬浮详情按问题明细展示样本名、问题总数；每条问题按“样本名·对象名称、处理等级、问题描述、对象 ID/无需定位信息”纵向排版，面板采用深色浮层视觉，保证问题层级清晰。问题明细区域根据视口高度限制在 240px 至 640px，超出后在浮层内容区内部纵向滚动，标题和问题总数保持可见。
- 规则校验记录来自 `GET /annotation-tasks/{id}/rule-check-records`；人工质检记录使用 `GET /annotation-tasks/{id}/quality-records`，详情页等宽展示规则记录与质检记录，以及结果、提交人、质检人和问题样本。
- 规则校验记录使用 `DmAppTable` 展示记录序号、校验时间、校验结果三列，无操作项；空数据保留表头并使用表格内置空态。
- 样本列表和规则校验记录的模块标题，以及样本总数，统一使用常规字重。
- 任务列表和详情顶部的开始、截止时间仅展示日期；规则校验记录保留具体创建时间。
- 普通标注任务提交质检经过二次确认，确认后刷新详情数据；`taskType` 为 `ITERATIVE_PRE_ANNOTATION` 时隐藏提交质检，改为显示“完成复核”，二次确认后调用 `POST /annotation-tasks/{annotationTaskId}/complete-iterative` 并刷新详情。
- 页面不做角色权限过滤，接口错误沿用统一请求处理。
- 详情加载成功后将任务展示名称写入路由 `meta.title`，离开详情页时清理动态标题。
- 详情页不在内容卡片内重复展示返回按钮和详情副标题，沿用主布局的“标注任务 / 当前任务”路由面包屑；工作台和提交质检按钮置于任务信息分割线下方，并与任务元信息保持同一行垂直居中。
- 详情头部上下内边距统一为 14px；样本列表标题与企业列表标题使用一致的字号和颜色，移除样本说明文字及总项数文案，问题数量胶囊与标题底部对齐。
- 样本列表卡片标题使用与项目管理列表卡片一致的左侧、顶部 20px 间距；标题下方及分页上方不显示分隔线。分页保留每页 30 条规则，并显示与其他列表页一致的当前范围和总数文案。
- 规则校验记录和质检记录移除标题辅助说明及标题分隔线；有记录时标题使用左侧 20px、顶部 20px 间距，无记录时隐藏标题行并统一居中展示空状态图案及“暂无规则校验记录”“暂无质检记录”。
- 列表页外层不产生纵向滚动条，统计卡片和分页始终保持在页面可见区域；任务表格仅在表体区域承载纵向滚动，窄屏下也必须保留可见滚动条。

## 接口与数据约束

- 列表使用 `GET /annotation-tasks`，服务端负责关键字、状态筛选、截止时间排序、分页和统计；前端不再计算或维护任务 Mock 数据。
- 详情使用 `GET /annotation-tasks/{id}`，样本由详情响应一次性返回，页面仅在内存中按 30 条/页切分。
- 规则校验记录使用真实分页接口；人工质检记录使用真实分页接口并在详情右侧展示。
- 工作台标签配置使用 `GET /annotation-tasks/{id}/label-config`；该接口不在详情页展示。标注员身份进入 pc-tool 使用静态入口 `/tool/pc/`，管理端通过 `VITE_PC_TOOL_URL`（未配置时回退当前域名 `/tool/pc/`）拼接 `taskId`、`clipId` 查询参数，并按任务状态追加模式：质检中为 `mode=qc`、返修中为 `mode=re`、已完成为 `mode=readonly`，其他状态不传 `mode`；`clipId` 取详情样本的后端 `itemId`，不使用固定测试值或管理端详情路由。CT 工作台另通过 `GET /annotation-tasks/ohif/{itemId}` 获取 `studyInstanceUID`，写入 `StudyInstanceUIDs` 后打开。
- 当前接口未提供项目名称、任务类型本地化名称等列表字段，列表缺失时展示占位符，不补造业务值。
- 任务列表使用封装的 `DmAppTable`：状态列使用内置枚举筛选，截止时间列使用内置排序，分页配置与质量方案页面一致（支持切换 10/20/50 条）。
- 截止时间排序由服务端作用于完整结果集：升序发送 `sortField=deadline&ascSort=true`，降序发送 `sortField=deadline&ascSort=false`；恢复默认顺序时不传排序参数，切换排序后回到第一页。
