# 标签管理页面需求

## 功能目标

完善 `/label-management` 标签管理页面，在保留固定无滚动布局的基础上，提供可浏览、搜索、展开和维护节点的左侧标签树，并根据当前选择在右侧展示分组详情或标签详情及其独立属性数据。本阶段仅提供详情查看，工具和属性操作按钮不绑定交互。

## 使用场景

用户通过主布局进入标签管理页面，在左侧浏览分组和标签，通过搜索快速定位节点，并选择分组或标签查看详情。标签树数据在 store 首次使用时自动加载，并可通过 `refresh()` 重新同步；用户可以创建、编辑和删除分组或标签，标签属性通过独立 API 按标签加载。

## 页面区域与展示内容

页面采用三段式结构：

1. 顶部说明卡片：保留页面层级、标题和说明区域的视觉位置；业务说明正文使用空白或通用占位内容，不展示具体标签数据。
2. 左侧 `LabelTreePanel`：展示标签总数、新增分组与新增标签按钮、搜索框以及由分组和标签组成的树。分组使用文件夹标识，标签统一使用 `TagOutlined` 标识。
3. 右侧 `LabelDetailPanel`：根据选择展示以下三种互斥状态：
   - 未选择节点或选择失效时，显示暂无数据图标和“选择分组或者标签查看详情”，不展示其他详情内容。
   - 选择分组时，仅展示分组名称和描述；描述为空时使用统一空值文案，不展示标签编码、工具按钮或属性区。
   - 选择标签时，展示标签名称、描述、编码和属性区；属性区包含静态新增按钮，属性卡片包含静态关联工具、编辑、删除按钮，本阶段均不绑定交互。

标签属性卡片按接口顺序展示名称、编码、描述、中文类型、默认值以及“必填”“只读”状态。数值属性仅展示已有的最小值、最大值和单位；枚举属性展示规范化后的选项及单选/多选信息；空默认值使用统一空值文案。

## 交互规则

- 分组和标签节点都允许选中，选中后统一对外触发 `select(node.id)`。分组收起时显示 `FolderOutlined`，展开时显示 `FolderOpenOutlined`。
- 头部第一个按钮显示“分组”并打开新增标签组弹窗。弹窗填写标签组名称、描述和父标签组；父标签组为仅包含分组节点的级联结构，并提供提交为 `parentId: 0` 的“无父标签组”选项。父标签组选择器支持内置级联搜索，但不允许通过清除按钮移除当前选择。
- `LabelGroupModal` 通过 `mode` 支持创建和编辑。创建时根据当前树节点计算默认父级；编辑时回填名称、父标签组和说明。修改父标签组会移动节点，不在界面校验自身、后代或循环关系。保存成功后刷新 store，展开保存后的父级路径并选中该分组。
- `LabelModal` 通过 `mode` 支持创建和编辑。标签名称和所属标签组必填，标签说明选填；编辑时回填现有字段。保存成功后刷新 store，展开保存后的父级路径、选中标签并触发 `select(labelId)`。
- 首次加载成功后保持未选择状态且不触发 `select`；刷新后原选择仍存在时保持选择，选择失效时清空选择并触发 `select(null)`。
- 搜索使用 `src/utils/tree.ts` 的 `deepFilter()`：标签名称命中时保留其祖先分组，分组名称命中时仅保留分组自身及其他独立命中的后代，不保留该分组的全部原始子树。
- 搜索关键字经过节流后再触发树过滤，避免连续输入时频繁递归计算。
- 搜索期间自动展开筛选结果中的分组；清空搜索后恢复开始搜索前的展开状态。
- 新增分组按钮可打开创建弹窗。新增标签按钮在任意分组或标签节点被选中时启用，没有选中节点时禁用。选中分组时默认使用该分组；选中标签时默认使用其直接父分组；标签没有父分组时默认“无父标签组”并提交 `parentId: 0`。弹窗仍允许手动切换所属标签组。
- 鼠标悬浮或键盘焦点进入节点行时，节点最右侧展示编辑和删除按钮；操作按钮不触发树选择或分组展开。
- 标签和空分组删除前显示确认框。分组的任意层级后代存在标签时，提示“{groupName} 分组下面有标签，不能删除！”且不调用删除接口。仅包含分组后代的分组不显示确认框，直接级联删除整个纯分组子树。
- 删除后刷新 store；当前选择仍存在时保留，失效时清空选择并触发 `select(null)`，不自动选择其他节点。搜索状态下删除后重新计算当前筛选结果。
- 页面保存左侧发出的选中节点 ID 并传给详情面板；详情面板通过 label store 的 `mapping` 获取节点，不在页面重复节点查询逻辑。
- 标签选中后按标签 ID 查询属性；快速切换节点时只接收当前标签对应的请求结果，旧请求不得覆盖新选择。
- 属性请求失败时清空当前属性列表并显示属性空态，但标签名称、描述、编码和静态按钮仍正常展示。
- 属性新增和编辑共用弹窗；仅属性编码必填，名称和描述选填。保存成功后立即更新当前标签的属性列表。
- 值类型支持 `number`、`text`、`date`、`boolean`、`enum` 和 `json`；切换类型时清空默认值和旧类型全部专属字段。
- 数值类型使用数字默认值、可选最小值与最大值以及单位；文本、日期和布尔类型分别使用文本框、日期选择器和是/否下拉框。
- 枚举类型支持添加和删除枚举项及多选开关；枚举名称、值和说明均可留空，保存时由属性 API 过滤全空项并补齐单边名称或值。
- 枚举项区域限制高度并在内部滚动，属性弹窗本身不产生滚动条；是否多选、是否只读和是否必填均使用 Switch。
- 每张属性卡片在编辑按钮左侧提供“关联工具”入口；标签详情和分组详情不提供标签级工具关联入口。
- 一个标签属性可以关联多个工具；同一工具只能选择一个具体工具属性。
- 未勾选工具时禁用工具属性下拉框，取消勾选时清空该工具属性。
- 弹窗取消或关闭时丢弃属性关联草稿；保存时过滤未选择工具属性的记录，允许保存空关联，重新打开后回显已保存的工具和属性映射。
- 不实现节点拖拽交互。

## 固定画布与状态处理

- 页面使用现有 `main` 主布局，路由地址固定为 `/label-management`。
- 页面根容器采用桌面端设计基准的固定最小画布尺寸；视口小于该尺寸时允许内容被裁切。
- 页面级禁止出现横向或纵向滚动条，内部面板也不创建独立滚动容器；通过裁切保证固定布局边界。
- 详情面板和属性容器使用固定高度及 `overflow: hidden`；属性数量超出可用高度时裁切，本阶段不增加滚动、分页或虚拟列表。
- 左侧标签树处理加载、请求失败、默认空数据和搜索无结果状态；请求失败时允许用户重试。
- 右侧标签属性区处理加载结果、空数据和请求失败状态；属性失败不影响标签基础信息。
- 页面应兼容项目现有浅色、深色主题令牌及常见内容溢出场景，溢出内容不得重新引入滚动条。

## 数据模型与接口依赖

- 标签树查询对接 `GET /label-nodes/tree`；API 层解包统一响应对象并返回 `data` 中的树形节点列表。
- 标签树节点字段与后端保持一致，使用 `id`、`parentId`、`nodeType`、`nodeName`、`nodeDescription`、`sortOrder` 和 `children`；`nodeType` 取值为 `GROUP` 或 `LABEL`。
- 标签 Store 的 `tree` 保留后端树结构并补充 `key`、`path`，`list` 从树递归展开为扁平列表；页面和组件不再使用 `pid`、`type`、`name`、`description` 等旧节点字段。

- 标签树查询 API 返回后端树形结构；Store 根据业务消费需要同时维护树形 `tree` 和扁平 `list`。
- 分组和标签共用后端节点字段，标签树节点不携带属性数组或工具数组，属性数据独立维护并通过 `labelId` 关联标签。
- 节点 `type` 在创建时确定，更新时不可修改；标签节点不维护颜色字段，树中统一使用 `TagOutlined` 标识。
- 节点新增、修改和删除分别对接 `POST /label-nodes`、`PUT /label-nodes/{labelNodeId}` 和 `DELETE /label-nodes/{labelNodeId}`；父节点、循环关系、删除约束和级联行为由后端最终校验。
- 节点请求使用 `parentId`、`nodeType`、`nodeName`、`nodeDescription`，根节点 `parentId` 固定为 `0`；更新请求按接口文档完整提交节点可编辑信息和不可变的 `nodeType`。
- 属性值类型直接使用接口枚举 `NUMBER`、`TEXT`、`DATE`、`BOOLEAN`、`ENUM` 和 `JSON`；属性字段使用 `id`、`attributeName`、`config`、`attributeDescription`、`sortOrder` 和 `toolBindings`。
- `config` 必须包含 `valueType`、`defaultValue`、`readOnly`、`required` 和 `constraint`；日期默认值使用 `yyyy-MM-dd` 字符串，枚举多选状态仅由数组形式的默认值在表单中推导，不作为接口字段提交。
- 枚举选项字段为可选 `value`、`label` 和 `description`。`value` 与 `label` 都为空时过滤；仅有 `value` 时将其字符串化补入 `label`；仅有 `label` 时将其同时补入 `value`；两者都有时保持原值。
- `constraint` 按文档承载类型约束：`NUMBER` 使用 `min`、`max`、`unit`，`TEXT` 使用 `maxLength`、`pattern`，`DATE` 使用 `minDate`、`maxDate`，`ENUM` 使用 `options`；不提交文档外字段。
- 属性列表由 `GET /labels/{labelId}` 的标签详情返回；属性新增、修改和删除分别对接 `/labels/{labelId}/attributes` 下对应接口，修改请求完整提交属性名称、配置和说明。
- 标签详情、属性及属性请求体直接使用后端 `attributeName`、`config`、`constraint`、`toolBindings` 字段，不建立另一套前端字段模型；成功但详情或属性数据缺失时使用明确空状态或抛出接口数据异常。
- 属性工具绑定通过 `PUT /labels/{labelId}/attributes/{attributeId}/tool-bindings` 整体覆盖保存，空数组表示清空关联。
- 工具固定定义与属性关联配置分开维护。`AnnotationTool` 包含 `value`、`name`、`description` 和固定 `properties`；关联配置按标签属性 `propertyId` 保存 `{ toolValue, toolPropertyCode }`，每条记录对应一个已选工具及其唯一具体工具属性。
- 内置工具为 `bbox`、`mask`、`recist`、`measure`、`lung_segmentation`；其固定属性分别为目标区域/长径/短径、轮廓/体积/分割范围、长径线/短径线、距离、段名/肺叶。
- 独立标签工具 Pinia store 提供工具定义、按标签属性读取和替换关联、初始化与刷新能力；读取和保存均使用防御性副本，`refresh()` 恢复五种固定工具并清空全部属性关联。本阶段不接入后端持久化，也不实现工具定义增删改查。
- 新增标签 Pinia store，使用 `shallowRef` 暴露原始扁平 `list`、完整 `tree`、简化 `simpleTree` 和可变 `mapping`，避免 Vue 深层代理，并提供 `initialize()` 与 `refresh()`。
- `tree` 通过现有 `flatToTree()` 生成并保留完整节点信息，为每个派生节点补充与 `id` 相同的 Ant Tree `key`，再使用 `deepSort()` 递归排序；每层分组排在标签前，同类型节点按 `name` 升序排列。
- `simpleTree` 使用排序后的 `tree` 和 `deepMap()` 生成，节点只保留 `value`、`label` 和 `children`；其中 `value` 对应原节点 `id`，`label` 对应原节点 `name`，顺序与完整树一致。
- `tree` 中每个节点包含从根节点到自身的 `path`；路径通过 `deepMap2()` 的已映射父节点在初始化时生成。`mapping` 使用节点 `id` 作为键、带 `key` 和 `path` 的增强树节点作为值；每次初始化成功后与三种数据结构一起重新计算。
- store 首次使用时自动请求节点列表，合并并发初始化请求；加载失败后允许重新初始化。
- 不新增第三方依赖；使用现有 Vue、Ant Design Vue、路由、国际化和样式能力。
- 页面可见结构文案遵循现有国际化约定；标签树直接展示 store 返回的名称，不在组件中硬编码业务数据。

## 验收标准

1. 访问 `/label-management` 可正常渲染标签管理页面。
2. 页面包含顶部说明卡片、可浏览的 `LabelTreePanel` 和随当前节点切换的 `LabelDetailPanel`。
3. 页面整体布局与已确认设计一致，左右区域比例、卡片边界和固定画布关系清晰。
4. 常见桌面端视口下页面不产生横向或纵向滚动条；较小视口允许固定画布被裁切但仍不显示滚动条。
5. 标签树支持搜索、展开、分组与标签选择；新增标签按钮在任意节点被选中时可用，并根据选中分组或标签父级计算默认所属标签组；分组和标签均可创建、编辑与按规则删除。
6. 标签 API 按接口文档完成节点增删改查，业务失败码透传后端消息，标签树节点不包含属性数组。
7. 标签 store 首次使用时自动加载数据；`list`、`tree`、`simpleTree` 和 `mapping` 使用浅层响应式引用，内部数据不被 Vue 深层代理，并可通过 `refresh()` 强制整体更新。
8. 标签树正确处理加载、失败、空数据和搜索无结果状态；首次加载保持未选择，选择失效时清空选择并触发 `select(null)`。
9. 未选择节点时显示“选择分组或者标签查看详情”；分组只显示名称和描述；标签显示名称、描述、编码和属性区。
10. 属性查询、创建和更新直接返回后端字段结构；请求体完整符合文档中的动态配置结构，不进行字段重命名或扁平化转换。
11. 属性删除和工具绑定保存携带标签 ID 与属性 ID；业务失败时展示后端消息，查询无属性标签时返回空数组。
12. 详情面板及属性容器保持固定无滚动布局，长内容截断或裁切，不撑破页面画布；浅色和深色主题下信息层级清晰。
13. 每张属性卡片在编辑按钮左侧提供关联工具入口；未勾选工具时禁用工具属性下拉框，取消勾选后清空该工具属性。
14. 一个标签属性可关联多个工具，同一工具仅可选择一个具体工具属性；保存时过滤未选择工具属性的记录并允许空关联，重新打开可回显关联，取消不修改已保存数据。
