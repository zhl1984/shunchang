# 质检任务页面需求

## 功能目标

提供质检任务列表和详情页，展示任务状态统计、搜索、筛选、分页、详情跳转、样本列表、规则校验记录和人工质检记录，并支持质检员对任务执行“通过/不通过”确认。

## 使用场景

- 质检员进入 `/quality-task` 查看自己的质检任务。
- 管理员进入 `/quality-task` 查看全部有效质检任务。
- 用户按任务名称搜索、按任务状态筛选，并进入 `/quality-task/:id` 查看或处理任务。
- 用户在详情页打开 pc-tool 定位样本，或提交质检通过/不通过结果。

## 字段与展示内容

列表页顶部展示四个统计卡片：全部、质检中、返修中、已完成。统计数据来自列表接口返回的 `summary`，不在前端自行推导。
统计卡片的标签和数值字体与标注任务页面保持一致：标签使用常规字重，数值使用与列表样本数量一致的默认界面字体和数字样式。
统计卡片不显示边框，标签和数字整体垂直居中，与项目管理页面保持一致。
统计卡片文字左侧展示与任务状态匹配的蓝色图标，图标置于浅蓝色圆形底中。

任务列表展示任务名称、任务状态、处理人、样本数量、截止时间和操作栏。任务名称使用 `taskName`，任务状态使用 `status`，处理人使用 `inspectorName`，样本数量使用 `sampleCount`，截止时间使用 `dueAt` 并仅展示日期。样本数量列的标题和内容均右对齐。操作栏提供“查看详情”入口。

详情页顶部展示任务名称、状态、处理人、样本数量、开始时间和截止时间；中部展示轮次信息和检查范围；下方展示样本列表、规则校验记录和人工质检记录。样本列表按分页展示，样本卡片展示样本序号、名称和修改结果；规则校验记录展示记录时间、规则内容、命中样本和证据对象；人工质检记录展示提交时间、提交人、质检人、结果和问题样本。

## 交互规则

- 搜索框输入任务名称，按 Enter 或清空时触发查询，并回到第一页。
- 表格状态筛选使用接口参数 `statusFilter`，枚举值为 `QUALITY_CHECKING`、`REWORKING`、`COMPLETED`。
- 截止时间列启用 `DmAppTable` 表头排序，由服务端对完整结果集排序；升序发送 `sortField=deadline&ascSort=true`，降序发送 `sortField=deadline&ascSort=false`，恢复默认顺序时不传排序参数，切换排序后回到第一页。
- 分页使用服务端分页，参数为 `pageNo` 和 `pageSize`，默认 10 条。
- 点击“查看详情”进入 `/quality-task/:id`，并追加主布局面包屑“质检任务详情”。
- 详情页“进入工作台”使用 `VITE_PC_TOOL_URL` 或同域 `/tool/pc/` 生成地址，并传递 `taskId`、`qualityTaskId`、`clipId` 与 `mode`；本地开发环境通过环境变量指向 dev 工作台，避免依赖未启动的本地 pc-tool 服务。
- 详情页存在样本时始终展示分页器；即使当前只有一页，也保留与标注任务详情一致的分页入口。
- 详情页样本卡片复用标注任务的悬浮问题明细；问题内容区根据视口高度限制在 240px 至 640px，超出后在浮层内部纵向滚动，标题和问题总数保持可见。
- 详情页提交质检结果前进行二次确认。提交通过传 `PASS`，提交不通过传 `FAIL`，成功后刷新详情和记录。

## 状态处理

- 列表和详情均处理加载、空数据和请求失败状态。
- 接口业务码非 `0` 时使用后端 `message`；响应结构缺失时使用模块兜底提示。
- 接口成功但 `data`、`summary` 或 `list` 缺失时视为异常响应，避免页面依赖空结构。
- 详情页加载成功后把任务名称写入路由 `meta.title`；组件卸载时清理动态标题。
- 直接访问详情地址时仍可加载详情，面包屑至少保留当前详情页路径。

## 接口依赖

- `GET /quality-tasks`：质检任务列表、分页、状态统计和截止时间排序；排序参数为 `sortField` 字符串及 `ascSort` 布尔值。
- `GET /quality-tasks/{qualityTaskId}`：质检任务详情和质检样本。
- `GET /quality-tasks/{qualityTaskId}/rule-check-records`：规则校验记录。
- `GET /quality-tasks/{qualityTaskId}/quality-records`：人工质检记录。
- `PATCH /quality-tasks/{qualityTaskId}/status`：提交质检通过或不通过。

当前页面不直接调用 Axios 或 `http` 实例，统一通过 `src/api/quality-task.ts` 暴露的业务 API 函数访问接口。

## 验收标准

- `/quality-task` 路由渲染真实列表页，不再显示 404 或开发中水印。
- `/quality-task/:id` 渲染真实详情页，并按参考图组织顶部信息、样本区和记录区。
- 详情页顶部任务信息与操作按钮在宽屏保持同一水平线；“通过”和“不通过”按钮使用一致的固定尺寸，窄屏时按布局规则换行。
- 页面视觉与参考图保持一致：顶部浅色统计卡片、白色列表容器、右上搜索框和表格操作链接。
- 质检任务列表顶部统计卡片使用 8px 圆角且不显示阴影。
- 搜索、状态筛选、截止时间排序和分页会调用真实列表接口；统计卡片使用接口返回 `summary`。
- 表格状态、日期和数量有稳定展示，空值显示占位符，不抛运行时异常。
- 详情页样本卡片、规则校验记录和质检记录能正常展示，点击样本可进入工作台。
- 样本问题较多时，悬浮问题明细不会超出常见屏幕高度，用户可在浮层内容区滚动查看全部问题。
- 详情页存在样本时展示分页器，单页数据也可看到当前页码。
- 详情页提交质检结果会调用真实接口，成功后刷新详情和记录。
- 页面文案全部通过 `qualityTask` 国际化键维护。
- 修改后通过格式化检查、ESLint、类型检查和相关测试；无法运行时如实说明。
