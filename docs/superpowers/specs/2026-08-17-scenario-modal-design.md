# 场景配置弹窗设计

## 目标与范围

为场景配置实现新增、查看、编辑和复制流程。四种模式共用一个从上到下连续滚动的弹窗，按固定顺序展示基础信息、标签选择、规则选择和质量方案。本期不使用步骤条、标签页、折叠面板或嵌套页面；删除功能仍不在本期范围内。

## 模式定义

- `create`：打开空白草稿并创建新场景。
- `view`：加载所选场景，禁用全部控件，隐藏选择类操作，底部仅保留关闭按钮。
- `edit`：加载所选场景，校验后更新原记录。
- `copy`：加载所选场景作为新草稿，名称追加 ` - 副本`，清空 `projectList`，并生成新 ID。标签、规则启用状态和质量方案全部继承。

弹窗标题和底部操作区固定，中间主体独立滚动。新增和复制模式的主按钮文案为“创建并检查配置”，编辑模式为“保存修改”，查看模式为“关闭”。提交期间禁止关闭弹窗和重复提交。

## 组件边界

`ScenarioModal.vue` 负责完整视觉结构、区块排列、模式文案、草稿初始化、基础信息、质量方案、统一校验和提交编排。

`ScenarioLabelSelector.vue` 负责标签树和已选标签卡片。该拆分仅用于控制代码复杂度，在界面上仍作为弹窗第二部分参与同一滚动流程。

`ScenarioRuleSelector.vue` 负责适用规则筛选、规则卡片以及全选和全不选，在界面上仍作为弹窗第三部分参与同一滚动流程。

场景配置页面负责选择当前列表行、打开和关闭弹窗，并在收到 `saved` 事件后刷新场景 Store。列表行已经包含完整场景数据，查看、编辑和复制不重复请求详情。

`ScenarioModal.vue` 内部维护提交状态，并根据模式调用新增或更新 API。保存成功后关闭弹窗并发出 `saved` 事件；页面不接触提交 API 和提交状态。

## 场景数据模型

```ts
interface Scenario {
  id: number;
  name: string;
  labelingType: string;
  description: string;
  labelList: Array<{
    id: number;
    name: string;
    labelType: "pre-annotation" | "manual";
  }>;
  ruleList: Array<{ id: number; enabled: boolean }>;
  qualityId: string;
  projectList: Array<{ id: number; name: string }>;
}
```

本期标注类型仅提供固定值 `Lung CT annotation`，该选项不接入国际化。

## 第一部分：基础信息

基础信息包含场景名称、标注类型和场景说明。场景名称和标注类型必填，提交前去除名称首尾空格；场景说明选填。

## 第二部分：标签选择

左侧面板使用 `labelStore.tree` 渲染带复选框的标签树。父子选择保持关联：勾选标签组时选择全部后代标签，父标签组支持半选状态。最终只有 `type` 为 `label` 的节点写入 `labelList`。

右侧面板以卡片形式展示全部已选标签。每张卡片提供场景专属的标签类型选择，取值为 `manual` 和 `pre-annotation`；新选标签默认使用 `manual`。查看模式仅显示类型徽标，不提供编辑控件。

至少需要选择一个标签。取消标签时，同时移除对剩余标签已经不再适用的规则。

## 第三部分：规则选择

从 `ruleStore.rules` 中筛选 `rule.labelId` 属于已选标签的规则作为当前适用规则。每条适用规则都必须存在于 `ruleList` 中，包括未启用规则。新出现的适用规则默认使用 `{ id, enabled: false }`，已经存在的规则保留原启用状态。

“全选”和“全不选”只影响当前适用规则。允许所有规则都处于关闭状态。因取消标签而不再适用的规则从草稿中彻底移除。

## 第四部分：质量方案

质量方案全局 Store 尚未实现，本期在弹窗内提供固定选项“肺部CT一级全量质检”，对应 ID 为 `quality-plan-001`，并将该字符串 ID 写入 `qualityId`。质量方案必选。后续接入质量方案 Store 时只替换选项来源，不改变场景表单与提交结构。

## 数据层

场景 Mock 数据从 `src/stores/scenario.ts` 移至 `src/api/scenario.ts`。API 模块提供列表、新增和更新方法，并返回深拷贝，防止弹窗草稿直接修改 Mock 数据源。

场景 Store 只保留全局列表初始化、加载状态和刷新能力。新增、编辑或复制成功后，场景页面先刷新 Store，再关闭弹窗。

## 校验与异常处理

新增、编辑和复制模式要求场景名称、固定标注类型、至少一个标签和质量方案完整。查看模式不触发校验。提交失败后弹窗保持打开并保留当前草稿。详情加载失败时关闭弹窗并显示错误提示。标签或规则依赖数据加载失败时，在对应区块显示错误状态。

## 测试策略

TypeScript 单元测试覆盖场景 API 的深拷贝与增改查行为、复制草稿转换、标签与规则同步以及校验辅助函数。Vue 组件只测试有意义的模式差异和用户交互，不通过读取源码字符串断言模板结构、CSS 选择器或 Less 声明。

## 验收标准

- 四种模式使用同一个纵向连续滚动弹窗。
- 弹窗主体滚动时，标题区和底部操作区保持可见。
- 标签组关联选择只保存标签叶子节点，并支持父节点半选。
- 每个已选标签可以独立配置和回显标签类型。
- 规则随已选标签自动同步，并保存启用和未启用状态。
- `qualityId` 使用字符串并引用已有质量方案。
- 新增、编辑和复制能够更新 API Mock 数据并刷新全局场景列表。
- 复制模式生成新 ID、名称追加 ` - 副本`，并清空项目引用。
- 查看模式不能修改任何字段。
