# 主布局面包屑设计

## 目标

所有使用主布局的非全屏路由统一在内容区头部显示面包屑。主布局根据路由变化维护默认路径列表，同时允许子页面通过注入方法基于导航前后的完整路径列表定制最终结果。

## 范围

- 修改主布局的面包屑状态管理与展示。
- 为面包屑路径项、更新回调和注入能力定义明确的 TypeScript 类型。
- 更新主布局的就近需求文档与集中需求文档。
- 不修改全屏路由，不新增 Pinia store、第三方依赖或后端接口。
- 保留用户已在 `src/layouts/main/index.vue` 中开始编写的面包屑结构，并在其基础上修正状态流与类型设计。

## 数据结构

每个面包屑路径项包含：

- `title`：展示标题。
- `path`：对应路由地址。
- `active`：是否为当前路径项。

路径列表使用完整数组替换，不依赖 `push` 等原地变更来表达一次路由导航的结果。

更新回调接收以下参数：

1. `route`：当前的标准化路由对象。
2. `oldPathList`：路由变化前保存的完整路径列表快照。
3. `newPathList`：根据当前路由生成的完整默认路径列表。

回调返回完整的最终路径列表。主布局提供的 `addPath` 方法调用该回调，并以回调结果整体重置当前 `pathList`。

## 状态流

主布局监听当前路由。发生路由变化时：

1. 复制并保存变化前的 `pathList`，避免后续更新影响旧值。
2. 从新路由生成完整的默认 `newPathList`。
3. 使用 `newPathList` 整体重置当前 `pathList`。
4. 保存本次导航的 `oldPathList` 与 `newPathList`，供子页面随后调用 `addPath` 时使用。

默认路径标题优先使用路由元信息中的动态 `meta.title`；不存在时使用 `meta.titleKey` 对应的国际化文案。主布局只处理自身承载的路由，因此登录页、404 等全屏页面不会显示该面包屑。

## 子页面扩展接口

主布局通过具名、带类型的 injection key 对外提供 `addPath(callback)`。子页面注入后可以组合旧列表和新列表，例如进入详情页时保留来源路径，再追加当前路由的默认路径。

`addPath` 不接收单个路径项，也不直接执行 `push`；它只接受回调，并以回调返回的完整数组替换当前列表。若回调返回空数组，则面包屑清空。

## 组件与职责

- `src/layouts/main/index.vue`：监听路由、维护路径快照、渲染面包屑、提供更新方法。
- 主布局附近的类型模块：声明路径项、回调、上下文和 injection key，使布局与子页面共享同一接口，避免字符串 key 和匿名对象注入。
- 路由配置继续负责提供 `titleKey` 与可选动态 `title`，不在页面中重复维护默认标题。

## 展示与交互

- 面包屑位于主内容区顶部、路由页面内容之前。
- 当前项使用 `active` 标识；非当前项可依据 `path` 导航，当前项仅展示标题。
- 路径项使用稳定的 `path` 作为渲染 key，不使用数组下标。
- 样式复用 Ant Design Vue 与项目现有间距工具类，并兼容浅色、深色主题和长标题溢出。

## 异常与边界

- 路由缺少 `title` 和 `titleKey` 时，不生成无标题路径项。
- 调用 `addPath` 前没有历史路径时，`oldPathList` 为空数组。
- 回调接收列表快照，不能通过修改入参间接改变当前状态；最终状态只取回调返回值。
- 连续路由变化时，每次导航都重新建立旧列表和默认新列表，避免沿用上一次页面定制后的临时引用。

## 验证

- 单元测试覆盖默认路径生成、动态标题优先级、旧列表快照、回调整体替换和空结果。
- 组件行为验证覆盖路由变化后面包屑更新，以及注入的 `addPath` 能定制最终列表。
- 运行相关 Vitest、ESLint、Prettier 检查、TypeScript 类型检查和生产构建。

## 验收标准

- 所有主布局业务路由显示由当前路由生成的默认面包屑，全屏路由不受影响。
- 路由变化后 `pathList` 被完整重置，并保留变化前的完整列表快照。
- 子页面可以通过注入的 `addPath(callback)` 读取 `route`、`oldPathList`、`newPathList`，并返回完整列表替换面包屑。
- 动态 `meta.title` 优先于国际化 `meta.titleKey`。
- 不覆盖工作区中与本需求无关的用户改动。
