# 首页首个业务菜单重定向设计

## 背景与目标

当前根路由 `/` 只加载主布局，没有明确的默认业务页面。登录用户访问根路由时，应自动进入其有权限访问且在侧边栏展示顺序中排在第一位的业务菜单。

## 范围

- 只调整根路由的导航决策，不修改业务权限协议和菜单组件。
- 不改变直接访问列表页、详情页或其他业务地址时的行为。
- 不新增接口、依赖或持久化状态。

## 路由选择规则

新增纯函数 `getFirstMenuPath(routes)`，接收当前用户已获准的业务路由集合，并按以下规则返回目标路径：

1. 仅保留 `meta.layout === "main"` 且 `meta.menu === true` 的菜单路由。
2. 先按 `meta.groupOrder` 升序排列菜单分组。
3. 同一分组内按 `meta.order` 升序排列菜单。
4. 返回排序后第一个菜单的 `path`。
5. 没有可用菜单时返回空字符串。

未配置的排序值沿用现有菜单投影规则，按 `0` 处理。排序结果相同时保持业务路由原有声明顺序。

## 导航流程

前置路由守卫继续负责用户初始化、认证校验和业务路由注册：

1. 等待用户 store 初始化。
2. 未登录用户访问 `/` 时，沿用认证逻辑跳转至登录页。
3. 已登录用户访问 `/` 时，先注册其业务路由，再从 `getRoutesForUser(user)` 的结果中计算首个菜单路径。
4. 找到目标路径时使用替换导航，避免根路由留在浏览器历史中。
5. 没有可用菜单时保留 `/`，不产生重定向循环。
6. 访问其他地址时继续使用现有动态路由重解析和 404 处理逻辑。

登录页检测到已有用户并跳转至 `/` 后，也会自然进入上述根路由流程。

## 测试设计

- 验证函数忽略详情路由等非菜单路由。
- 验证函数按 `groupOrder` 和 `order` 返回最终菜单顺序中的第一项，而不是简单取数组首项。
- 验证无可用菜单时返回空字符串。
- 验证已登录用户访问 `/` 时获得替换导航目标。
- 保持现有动态路由注册、直接访问业务页和 404 测试通过。
