# 标签属性关联工具设计

## 目标

将标签管理详情面板中的工具关联从标签维度调整为标签属性维度。标签本身不再关联工具；每个标签属性可以关联多个标注工具，并为每个工具选择一个具体工具属性。

## 界面调整

- 删除标签详情头部原有的“工具”按钮。
- 在每张属性卡片的操作区增加工具关联按钮，位置在编辑按钮左侧。
- 点击工具关联按钮时，打开当前属性专属的关联弹窗。
- 新弹窗独立实现，不复用旧的标签级关联弹窗。
- 弹窗展示当前属性名称、工具总数以及全部可用工具。
- 每个工具占一行，包含工具复选框、名称、说明和工具属性单选下拉框。
- 工具未勾选时，下拉框禁用；勾选后启用。
- 下拉框选项来自该工具自身的属性列表。
- 取消勾选工具时，清除该工具已经选择的工具属性。

## 数据模型

标签属性与工具的单条关联使用以下业务结构：

```ts
type LabelPropertyToolAssociation = {
  toolValue: string;
  toolPropertyCode: string;
};
```

关联数据以标签属性 `propertyId` 为键维护。一个标签属性可以保存多条关联，因此可以同时关联多个工具；同一个工具在同一标签属性下最多保存一条关联，并且只能选择该工具的一个工具属性。

标签节点不再包含或维护工具关联。旧标签级关联结构、操作方法、辅助逻辑、弹窗和对应测试全部删除，不保留兼容逻辑。工具定义及其固定属性仍由 `label-tool` store 统一提供。

## 交互与状态

- 打开弹窗时，根据当前属性 ID 读取已保存的关联并回显勾选状态和工具属性。
- 用户可以不选择任何工具，保存空列表表示当前属性没有工具关联。
- 工具被勾选但没有选择工具属性时，该条记录无效，保存时过滤。
- 保存成功后整体替换当前属性的关联草稿并关闭弹窗。
- 取消或关闭弹窗时丢弃本次草稿，不修改 store 数据。
- 属性切换或弹窗重新打开时重新初始化草稿，避免不同属性之间串用状态。

## 组件与状态边界

- `LabelDetailPanel.vue` 负责记录当前操作的标签属性，并控制新弹窗开关。
- 新建 `LabelPropertyToolAssociationModal.vue`，负责工具选择、工具属性选择、草稿初始化和保存。
- `src/stores/label-tool.ts` 负责工具定义，以及按属性 ID 读取和替换关联数据。
- 用户可见文案全部维护在国际化语言包中。

## 异常与边界

- 当前属性不存在时不打开弹窗。
- 工具定义没有属性时，其下拉框保持禁用，且不会产生有效关联。
- 已保存的工具或工具属性已从定义中移除时，初始化草稿时忽略失效关联。
- 删除标签属性时，本次调整不额外扩展 API 协议；属性关联属于前端 mock store 状态，后续接入后端时由 API 层完成协议转换和级联清理。

## 验收标准

1. 标签详情头部不再展示标签级工具按钮。
2. 每张属性卡片的编辑按钮左侧展示工具关联按钮。
3. 点击按钮打开的弹窗明确展示当前属性，并列出全部工具。
4. 勾选工具后才能选择该工具的一个工具属性。
5. 同一属性可以保存多个工具关联，重新打开时正确回显。
6. 取消勾选会清除对应工具属性，空关联可以保存。
7. 旧标签级弹窗、关联结构、辅助逻辑和测试均已移除。
8. 国际化、类型检查、格式检查和相关测试通过。
