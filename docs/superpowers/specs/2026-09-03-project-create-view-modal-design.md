# 项目新建与查看弹窗设计

## 目标与范围

项目管理页面新增“新建项目”和“查看项目”弹窗。两种模式复用同一套四步结构：基础信息、标注场景、团队成员、数据来源。

功能按模块分阶段交付。第一阶段只完成弹窗骨架、步骤切换、组件接口、状态缓存和数据转换边界；第二阶段再逐个开发步骤内的字段、校验、选项接口和交互细节。

## 弹窗模式

弹窗接收 `create` 或 `view` 模式。新建模式从空的分步草稿开始；查看模式根据 `projectCode` 加载详情，将后端详情转换为分步草稿后展示，所有控件保持只读或禁用。

新建模式的步骤条不可点击，只能通过上一步和下一步顺序切换。查看模式不执行校验，并允许点击任意步骤。两种模式都保留步骤条和前后导航，查看模式最后一步只提供关闭操作。

弹窗遵循表单弹窗规范：居中、最大高度 `90vh`、内容区内部滚动、标准 Header/Body/Footer、Footer 操作右对齐。提交期间显示 Loading 并禁用会导致重复提交或丢失状态的操作。

## 组件结构

`ProjectModal.vue` 负责弹窗会话和业务编排，包括模式、当前步骤、步骤配置、分步草稿、详情加载、导航与最终提交。

四个步骤组件分别为：

- `ProjectBasicInfoStep.vue`
- `ProjectSceneStep.vue`
- `ProjectMemberStep.vue`
- `ProjectDataSourceStep.vue`

步骤使用动态组件渲染，并包裹在 `KeepAlive` 中。切换步骤不会销毁组件，因此用户返回前一步时可继续编辑原状态。关闭弹窗时重置会话 key，销毁旧缓存并清理草稿、校验状态和详情数据。

## 步骤组件协议

每个步骤只负责自己的内部表单状态、字段展示和校验，通过 `defineExpose` 统一暴露：

```ts
interface ProjectStepExpose<TForm> {
  validate: () => Promise<void>;
  getForm: () => TForm;
}
```

`validate()` 采用与 Ant Design Vue 表单一致的 Promise 语义。校验失败时 reject，由步骤组件显示错误并定位首个错误字段。`getForm()` 返回当前步骤数据的副本，外层不得直接持有或修改组件的内部响应式对象。

步骤组件接收当前模式和初始化表单数据：

```ts
interface ProjectStepProps<TForm> {
  mode: ProjectModalMode;
  modelValue: TForm;
}
```

第一阶段四个步骤只实现结构占位和统一协议，不提前虚构具体选项或业务数据。

## 分步表单模型

前端不在弹窗内维护与后端相同的扁平大对象，而是按步骤拆分：

```ts
interface ProjectFormDraft {
  basic: ProjectBasicInfoForm;
  scene: ProjectSceneForm;
  members: ProjectMemberForm;
  dataSource: ProjectDataSourceForm;
}
```

字段归属如下：

- 基础信息：项目名称、负责人、截止日期、项目描述。
- 标注场景：标注类型、标注场景。
- 团队成员：标注员、一级质检员、二级质检员等分层成员。
- 数据来源：数据集、数据类型、每批样本数、自迭代开关及配置。

最终字段名和必填规则以 `src/api/project.md` 及第二阶段确认的接口为准。详情接口当前未返回标注员和质检员，未确认前成员表单使用明确的空集合默认值，不生成模拟成员。

## 数据流与转换

新建模式采用逐步快照汇总：

```text
点击下一步
  -> 当前步骤 validate()
  -> 当前步骤 getForm()
  -> 覆盖 ProjectFormDraft 中对应步骤快照
  -> 激活下一步骤
```

上一步不校验、不采集。用户返回并修改后，再次点击下一步会使用最新表单覆盖旧快照。第四步点击创建时执行相同的校验和采集，再将完整草稿转换为创建请求参数。

查看模式的数据流为：

```text
GET 项目详情
  -> fromProjectDetail(detail)
  -> ProjectFormDraft
  -> 按步骤分发初始化数据
```

创建模式的数据流为：

```text
四段表单快照
  -> toCreateProjectParams(draft)
  -> POST 创建项目
```

`fromProjectDetail()` 与 `toCreateProjectParams()` 放在项目弹窗目录的 `utils.ts`，作为后端协议与前端表单模型之间的唯一转换边界。步骤组件不直接依赖后端 DTO。API 方法仍统一维护在 `src/api/project.ts`。

## 异常与状态处理

- 新建模式校验失败时保持当前步骤，不采集快照、不切换步骤。
- 查看详情加载期间显示 Loading；加载失败时弹窗保留明确错误状态，不渲染不完整表单。
- 详情字段缺失时由转换函数按接口契约提供安全默认值，尤其避免数组、嵌套配置和成员数据导致运行时异常。
- 创建提交期间禁用关闭、上一步和创建操作，避免重复提交和状态丢失。
- 创建成功后关闭弹窗，并通知项目管理页面刷新列表和统计信息。
- 关闭弹窗后清空当前步骤、草稿、详情、校验状态和 `KeepAlive` 缓存。

## 第一阶段测试

- 新建模式只有当前步骤校验成功后才能进入下一步。
- 校验失败时不调用快照合并且不切换步骤。
- 返回修改后再次前进会覆盖该步骤旧快照。
- 查看模式允许点击步骤条且不调用 `validate()`。
- 步骤切换后内部状态仍在；关闭并重新打开后旧状态消失。
- `fromProjectDetail()` 能把详情安全拆分为四段表单。
- `toCreateProjectParams()` 能把四段表单正确汇总为创建参数。
- 最后一步能够得到完整创建参数，但第一阶段不实际发起创建请求。

## 后续阶段

第二阶段按基础信息、标注场景、团队成员、数据来源的顺序逐个开发。每个模块开始前单独确认字段、校验、选项来源、联动规则和详情回显协议；其中团队成员必须等待后端补充详情字段或提供独立查询接口。
