# 成员管理页面需求

## 功能目标

还原产品原型中的成员管理界面，集中展示成员角色、菜单权限和工作分组入口，为后续接入成员管理接口提供页面基础。

## 使用场景

- 管理员按角色查看平台成员及账号状态，并核对角色菜单权限。
- 管理员通过姓名、账号、邮箱或手机号筛选成员。
- 管理员进入添加成员或工作分组流程。

## 字段与展示内容

- 页面头部展示模块名称、成员总数、功能说明和主要操作。
- 角色卡展示系统管理员、项目经理、标注员、质检员的人数及职责摘要。
- 权限列表展示菜单名称、所属模块和允许状态。
- 成员列表展示姓名、角色、登录状态、所属分组、最后登录时间和创建时间，不展示备注列。

## 交互规则

- 默认选择“系统管理员”，点击角色卡同步刷新权限和成员列表。
- 搜索框按姓名、账号、邮箱或手机号即时过滤当前角色成员。
- 角色和所属分组列按接口返回的 `roleId`、`workGroupId` 执行筛选，筛选选项和单元格继续展示对应名称；筛选值与记录字段必须使用同一数据类型。
- 添加成员按钮打开录入弹窗，并通过成员创建接口提交表单。
- 成员创建成功后立即刷新共享成员集合并回到列表第一页；刷新完成后再关闭弹窗，使新账号无需刷新页面即可看到。
- 页签可在“成员与权限”和“工作分组”之间切换。

## 状态处理

- 搜索无结果时展示空状态。
- 接口加载中展示加载状态，接口失败时交由统一 HTTP 错误处理并保留可恢复的空状态。
- 成员和工作分组数据来自成员管理 API；菜单权限沿用页面内置的角色权限配置，不请求权限接口。
- 成员与工作分组请求均完成后，共享 Store 按成员的 `workGroupId` 组合“分组节点 → 成员节点”树；空分组仍保留，未分组或引用不存在分组的成员作为根级成员节点保留，避免成员丢失。完整树再经 `deepFilter` 生成 `annotatorTree` 与 `qualityTree`：分别剔除 `nodeType === member && roleId !== 3`、`nodeType === member && roleId !== 4` 的成员节点，并同步去掉过滤后没有成员的分组。
- 分组节点直接使用接口返回的 `id` 作为 `key`、`groupName` 作为 `label`；成员节点直接使用接口返回的 `id` 作为 `key`、`userName` 作为 `label`，不生成额外前缀或虚拟分组数据。

### 添加成员弹窗

- 弹窗视觉基线与项目管理新建项目、数据集管理创建数据集弹窗保持一致：使用标准标题头、表单主体和底部操作区，统一内容内边距、字段间距、控件尺寸和主题变量。

- 弹窗字段包括成员姓名、登录账号、手机号、邮箱、初始密码、所属分组、角色和职责说明。
- 姓名、登录账号、初始密码和角色为必填项；手机号、邮箱和所属分组可选，邮箱填写后仍需校验格式。手机号未填写时不提交该请求字段，避免空字符串触发后端格式校验。
- 系统管理员和项目经理不可选择工作分组；标注员和质检员可从已有工作分组中选择。
- 默认角色为当前选中的角色，点击取消或关闭不提交数据。

### 成员详情弹窗

- 点击成员列表中的详情操作，打开成员详情弹窗；弹窗仅展示数据，不支持编辑或提交。
- 弹窗展示成员姓名、登录账号、手机号、邮箱、初始密码占位、所属分组、角色和职责说明。
- 详情弹窗支持关闭按钮、右上角关闭图标和遮罩关闭，不改变成员列表筛选和当前角色。

## 接口依赖

- 创建成员及工作分组新增、编辑、删除接口返回 HTTP 状态 400 或业务 `code` 为 `400` 时，展示后端返回的 `message`，且不执行成功后的刷新和提示。
- 新增成员及工作分组弹窗由接口结果控制关闭：成功后关闭，返回 400 或请求失败时保留弹窗和当前表单内容。

- `src/api/member-management.ts` 对接 OpenAPI 中的成员、角色权限和工作分组接口。
- 成员列表支持关键字、角色 ID、页码和分页大小；创建成员使用登录账号、初始密码、姓名、手机号、邮箱、角色 ID、职责说明；所属分组有值时额外提交对应分组 ID（`workGroupId`）。
- 工作分组支持列表查询、创建、详情、编辑和删除；编辑时可提交完整成员 ID 集合。
- 所有接口由 API 层统一处理 `code/message/data` 响应包装，页面和组件不直接使用 Axios。
- `src/stores/member.ts` 以 `member` 为 Store 名称，统一缓存成员、工作分组、完整关系树以及标注员树、质检员树，并在初始化或 CRUD 刷新时整体替换五份集合。

## 验收标准

- 在主布局内的视觉层级、间距、颜色、卡片结构和默认选中状态与原型截图一致。
- 角色切换、搜索、页签和添加成员弹窗可正常操作。
- 创建成员成功后自动刷新成员列表并回到第一页，新账号无需刷新页面即可看到。
- 成员与工作分组加载完成后可从共享 Store 读取完整关系树、标注员树和质检员树；每个成员只出现一次，完整树中空分组可见，未分组成员不会丢失；标注员树仅保留 `roleId === 3` 的成员，质检员树仅保留 `roleId === 4` 的成员。
- 常见桌面宽度下布局稳定，窄屏可自然换行，并适配深色主题。
- 用户可见文案由国际化语言包提供，类型检查和 ESLint 通过。

## 工作分组列表

- 工作分组页签展示分组名称、用途、使用状态、分组说明、成员数量和成员标签。
- 当前原型包含医学标注一组、自动驾驶标注组和核心质检组三个分组。
- 每个分组卡右上角提供编辑和删除入口图标；具体提交接口待后端协议确认。
- 点击删除入口弹出危险操作确认框，提示删除后成员恢复为未分配；接口未确认前不修改演示数据。

## 页面组件职责

- 成员与权限页签独立负责角色筛选、权限投影、成员搜索和成员列表展示。
- 工作分组页签独立负责分组卡片、成员标签和分组操作入口展示。
- 页面入口只负责页签切换、页面头部和成员弹窗编排。
- 添加成员与成员详情复用同一个成员弹窗组件，通过模式切换编辑态和只读态。

### 添加分组弹窗

- 弹窗视觉基线与项目管理新建项目、数据集管理创建数据集弹窗保持一致：使用标准标题头、表单主体和底部操作区，统一内容内边距、字段间距、控件尺寸和主题变量。

- 字段包含分组名称、分组说明、分组用途和成员选择。
- 分组名称与用途必填，说明和成员可选。
- 标注用途仅展示标注员，质检用途仅展示质检员；切换用途时清除不符合角色的已选成员。
- 本期仅实现前端校验和提交事件，不假设后端保存接口。
