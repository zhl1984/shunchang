# 场景配置需求

## 功能目标

在 `/scenario-config` 提供全局场景配置列表，并支持新增、查看、编辑和复制场景。

## 数据结构

`Scenario` 包含 `id`、`name`、`labelingType`、`description`、`labelList`、`ruleList`、`qualityId` 和 `projectList`。

## 列表与弹窗交互

场景列表支持搜索和分页。新增、查看、编辑、复制按钮打开场景弹窗；删除按钮打开二次确认框。

- `projectList` 为空时允许查看、编辑、复制和删除。
- `projectList` 不为空时只允许查看和复制；编辑与删除按钮禁用，并通过 Tooltip 说明场景已被项目引用。
- API 层必须同时阻止更新或删除已被项目引用的场景，避免绕过界面约束。
- 删除确认框显示场景名称并使用危险确认按钮；成功后刷新列表，删除当前页最后一条时自动回退上一页。

弹窗使用从上到下连续滚动的单页布局，依次展示基础信息、标签选择、规则选择和质量方案。弹窗标题区和底部操作区固定，只有中间内容区域滚动。

- 新增模式使用空白表单创建场景。
- 查看模式回显完整场景，全部控件只读，底部仅保留关闭按钮。
- 编辑模式回显原场景并更新原记录。
- 复制模式继承标签、规则启用状态和质量方案，名称追加 ` - 副本`，清空项目引用并创建新记录。
- 标签树只能通过 Checkbox 改变勾选状态，点击节点本身不选中；勾选标签组时关联选择全部后代标签，并支持父节点半选，最终只保存实际标签节点。
- 每个已选标签维护场景专属的 `labelType`，取值为 `manual` 或 `pre-annotation`；新选标签默认使用 `manual`。标签树与已选标签区域保持固定高度并分别在内部滚动；已选标签每行展示两个，右侧使用标签在两种类型间点击切换，预标注使用成功色，手动使用信息色。查看模式仅展示状态标签。
- 规则仅展示 `labelId` 属于已选标签的规则；所有当前适用规则都写入 `ruleList`，包括 `enabled: false` 的规则。
- 已选标签变化导致适用规则集合变化时，当前全部适用规则默认启用。
- 取消标签后，自动移除已经不再适用的规则。
- 场景名称、标注类型、至少一个标签和质量方案必填；场景说明选填，规则允许全部关闭。

## 接口与状态

- 场景 Mock 数据以及列表、新增和更新操作统一维护在 `src/api/scenario.ts`。
- 初始 Mock 列表同时包含未引用场景和已被项目引用场景，便于验证编辑、删除禁用状态。
- 场景 Store 只负责全局列表初始化、加载状态和刷新，不直接维护 Mock 数据。
- 标签树通过标签 Store 获取，规则通过规则 Store 获取。质量方案全局 Store 尚未实现，本期弹窗仅提供固定选项“肺部CT一级全量质检”；后续接入质量方案 Store 时保持 `qualityId` 提交结构不变。
- 列表行包含弹窗需要的完整场景数据，查看、编辑和复制直接使用当前行，不重复请求详情。
- 弹窗内部维护提交状态并调用新增或更新 API；成功后发出 `saved` 事件，由页面刷新场景 Store。

## UI 规范

- 页面标题卡片、数据卡片、操作按钮和独立分页与规则中心页面保持一致。
- 页面专属内部类名使用 `scp-` 短前缀。
- 表格操作列使用全局 `table-actions-cell` 和 `table-actions` 样式。
- 弹窗四个区块使用编号标题和独立卡片，但保持一个连续滚动页面，不使用步骤条、标签页或折叠面板。

## 验收标准

- `/scenario-config` 使用主布局并显示在配置中心菜单。
- 列表展示场景名称、标注类型、标签、质量方案、项目引用和操作。
- 列表正确处理加载、空数据、搜索和分页状态。
- 新增、查看、编辑和复制使用同一个纵向连续滚动弹窗。
- 标签组关联选择只保存标签叶子节点，并正确展示半选状态。
- 标签类型、适用规则及规则启用状态能够正确回显和保存。
- `qualityId` 使用字符串并引用已有质量方案。
- 复制场景生成新 ID、名称追加 ` - 副本`，并清空项目引用。
- 查看模式不能修改任何字段。
- 已被项目引用的场景不能编辑或删除。
