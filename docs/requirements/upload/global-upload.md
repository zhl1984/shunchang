# 全局上传任务需求

## 功能目标

提供跨页面共享的大文件上传任务管理能力，基于 Tus 协议支持分片、暂停、失败重试和断点续传，并在主布局用户信息区域提供任务提醒与进度入口。

## 使用场景

- 业务页面通过 `useUpload()` 将本地文件加入全局上传队列。
- 用户切换页面时上传任务继续运行，不依赖当前业务页面存活。
- 用户关闭页面或刷新前，存在未完成任务时收到浏览器原生离开提示。
- 用户刷新后重新选择原文件，系统恢复对应任务并通过 Tus offset 继续上传。
- 用户从 Header 用户区域查看未完成任务数量和详细进度。

## 技术方案

- `@uppy/core`：任务队列、状态、并发与生命周期。
- `@uppy/tus`：Tus 分片上传、offset 查询、暂停与继续。
- `@uppy/golden-retriever`：IndexedDB 持久化任务元数据和可恢复状态。
- `@uppy/dashboard` 不作为 UI 依赖；任务列表和进度弹窗使用现有 Vue 与 Ant Design Vue 组件实现。
- 后端按 Tus 协议提供创建、HEAD offset、PATCH 分片和 DELETE 取消能力。

## 数据与展示内容

- 任务 ID、文件名、文件大小、文件指纹、上传状态、已上传字节数、总字节数、进度、错误信息和 Tus 上传 URL。
- 未完成状态包括 `uploading`、`paused`、`error` 和等待重新选择文件的 `needs-file`。
- `completed`、`cancelled` 任务不计入 Header 未完成数量。
- Header 有未完成任务时显示明显红色徽标和数量；无未完成任务时不显示上传任务菜单项。
- 上传任务菜单项点击后打开 Modal，展示任务列表、进度、状态、暂停/继续、重试、重新选择文件和取消操作。

## 交互规则

- `useUpload()` 暴露添加文件、暂停、继续、重试、取消和重新绑定原文件的方法。
- 新文件加入后立即进入 Uppy 队列并开始 Tus 上传。
- 页面 `beforeunload` 仅在存在未完成任务时触发浏览器原生离开确认；不自定义浏览器无法控制的提示文案。
- 刷新恢复时不自动假设浏览器仍拥有原始 File 对象；任务先进入 `needs-file`，用户重新选择文件后校验文件指纹。
- 文件指纹不匹配时禁止继续原任务，并明确提示用户选择原文件或新建任务。
- 暂停、继续、重试、取消均通过全局 store 调度，不由 Header 组件直接操作 Uppy 实例。
- Header 任务菜单只在未完成数量大于 0 时渲染。

## 状态处理

- `uploading`：展示实时进度和速度。
- `paused`：展示继续操作。
- `error`：展示错误信息和重试操作。
- `needs-file`：展示重新选择文件操作。
- `completed`：展示完成状态，但不进入未完成提醒；是否保留在历史列表由后续需求决定。
- 用户登出或权限失效时，不静默删除本地任务；由上传层按 Tus 错误转换为可见错误。

## 接口依赖

后端需要提供 Tus 兼容端点和鉴权方式；具体 URL、请求头、元数据字段和 CORS 配置待后端协议确认后接入。前端本期只建立适配边界，不实现自定义分片协议。

## 验收标准

- 业务页面可以通过 composable 添加一个或多个任务。
- 大文件由 Tus 负责分片上传，暂停后可以继续，失败后可以重试。
- 未完成任务在 Header 显示红色徽标和数量；无任务时不出现进度菜单。
- 点击任务菜单可以打开进度 Modal，操作不会绕过全局上传状态。
- 刷新前有未完成任务时触发浏览器原生离开提示。
- 刷新后任务进入重新选择文件状态，选择相同文件后可继续 Tus 断点上传。
- 类型检查、Lint、测试和构建通过，不新增自定义协议实现。
