## 一、开发目标

实现“我的标注与返修任务”模块，覆盖以下能力：

1. 查看任务聚合状态统计。
2. 按聚合状态筛选任务。
3. 按任务名称、项目名称、当前执行人搜索任务。
4. 使用服务端分页浏览任务列表。
5. 查看任务详情、样本列表、规则校验记录和质检记录。
6. 样本列表支持分页，默认每页 30 条、每行 5 条。
7. 从任务、样本或最新质检问题样本进入对应工作台。
8. 在详情页执行标注员“提交质检”和质检员“通过/不通过”操作。
9. 所有流程动作执行前展示二次确认弹窗。

管理端负责查询、展示、跳转和流程动作触发；标注内容修改、质检内容填写及工作台内提交仍由工作台完成。

## 二、明确业务口径

### 2.1 状态模型

任务状态分为聚合状态和具体子状态：

| 层级     | 状态   | 说明                                             |
| -------- | ------ | ------------------------------------------------ |
| 聚合状态 | 标注中 | 包含普通标注和复核等标注阶段子状态               |
| 聚合状态 | 质检中 | 进入质检流程的任务                               |
| 聚合状态 | 返修中 | 需要标注员根据质检结果返修的任务                 |
| 聚合状态 | 已完成 | 当前任务流程结束                                 |
| 子状态   | 复核中 | 归入“标注中”统计和筛选，但列表可展示“复核中”标签 |

要求：

- 列表 Tab 只展示“全部、标注中、质检中、返修中、已完成”。
- “标注中”筛选必须包含 `复核中` 子状态。
- “标注中”统计数量必须包含所有标注阶段子状态。
- 前端不自行猜测后端原始状态映射；接口应返回聚合状态和具体状态，或提供稳定的状态映射字段。

### 2.2 权限边界

- 菜单权限由现有路由和登录后的菜单权限控制。
- 页面内部不做角色权限判断，不做“仅本人任务”等前端过滤。
- 页面只展示接口返回的数据和接口允许当前场景使用的业务结果。
- 接口返回 401、403、404 等错误时，沿用现有 `src/api/http.ts` 统一错误处理。

### 2.3 工作台边界

- 工作台负责标注修改、质检填写、问题处理和工作台内提交。
- pc-tool 使用静态入口 `/tool/pc/`，标注员身份进入时管理端通过 `VITE_PC_TOOL_URL`（未配置时回退当前域名 `/tool/pc/`）拼接 `taskId`、`clipId` 查询参数，并按任务状态追加模式：质检中为 `mode=qc`、返修中为 `mode=re`、已完成为 `mode=readonly`，其他状态不传 `mode`；`clipId` 取任务样本的后端 `itemId`。
- 前端不得根据项目名称、任务标题、数据类型关键词推导工作台 URL，也不得使用固定任务或样本 ID。
- 点击具体样本或质检问题样本时，复用同一入口并传入当前样本的 `itemId`，由 pc-tool 按 task -> item -> frame 加载并定位。
- CT 工作台打开前调用 `GET /annotation-tasks/ohif/{itemId}` 获取 `studyInstanceUID`，不得使用固定测试值。

## 三、列表页需求

### 3.1 页面结构

1. 页面标题：我的标注与返修任务。
2. 页面说明：标注任务只显示聚合状态：标注中、质检中、返修中、已完成。
3. 状态统计卡：标注中、质检中、返修中、已完成。
4. 状态筛选 Tab：全部、标注中、质检中、返修中、已完成。
5. 搜索框。
6. 任务列表。
7. 分页。

### 3.2 任务列表字段

| 字段       | 规则                                         |
| ---------- | -------------------------------------------- |
| 任务图标   | 常规任务、训练任务可使用不同 Ant Design 图标 |
| 任务名称   | 优先使用接口返回的展示名称                   |
| 任务类型   | 常规任务、训练任务                           |
| 项目名称   | 支持搜索                                     |
| 当前执行人 | 支持搜索                                     |
| 样本数量   | 使用接口真实值                               |
| 开始时间   | 使用统一格式化函数，仅展示日期               |
| 截止时间   | 使用接口真实值，仅展示日期                   |
| 具体状态   | 例如标注中、复核中、质检中、返修中、已完成   |
| 聚合状态   | 用于 Tab 筛选和统计归类                      |
| 操作       | 查看详情                                     |

### 3.3 列表交互

- 搜索范围：任务展示名称、项目名称、当前执行人。
- 搜索和状态切换后回到第 1 页。
- 默认分页大小建议为 10 或 20，最终以接口约定为准。
- 列表分页使用服务端分页，页面不对完整数据集做本地切片。
- 加载中显示 Table/List loading。
- 无数据显示普通空态。
- 搜索无结果显示搜索空态。
- 请求失败显示错误状态和重试入口。
- 搜索或翻页产生并发请求时，只允许最后一次请求更新页面。
- 点击“查看详情”进入独立详情路由 `/annotation-task/:id`。

## 四、详情页需求

### 4.1 页面结构

1. 返回按钮。
2. 任务类型、任务名称、具体状态。
3. 当前执行人、样本数量、开始日期、截止日期；日期不展示具体时间，顶部不重复展示项目名称说明。
4. 复核标签范围说明（接口有返回时展示）。
5. 右上角工作台和流程动作按钮。
6. 样本列表。
7. 规则校验记录与质检记录双栏区域，约 7:3。

详情路由：

```text
/annotation-task/:id
```

详情路由与列表路由平级注册，不作为列表页子路由，不参与侧栏菜单展示；访问时仍保持“标注任务”菜单高亮。现有 `getActiveMenuPath()` 已支持父路径匹配。详情数据加载成功后将任务展示名称写入 `meta.title`，离开详情页时清理动态标题。

### 4.2 详情页按钮

标注任务详情：

- 进入工作台。
- 提交质检。

质检任务详情或质检场景：

- 进入工作台。
- 通过。
- 不通过。

当前标注任务页面实现标注员提交质检和人工质检记录展示；标签配置仅供标注工作台使用，重新指派接口已纳入 API 层，页面交互按后续需求接入。

### 4.3 二次确认弹窗

点击上述流程动作后，必须先打开居中二次确认弹窗，确认样式参考提供的删除场景图片：

- 左侧警告图标。
- 标题。
- 场景化确认说明。
- 取消按钮。
- 确认按钮。
- 危险操作使用危险色确认按钮。

文案不得散落在组件中，统一放入国际化语言包；最终文案按具体场景调整。

交互要求：

- 点击取消不调用接口。
- 点击确认只调用一次对应接口。
- 请求中禁用当前动作，防止重复点击。
- 成功后刷新详情和列表统计。
- 失败时保留当前页面，沿用现有错误提示机制。

## 五、样本列表需求

### 5.1 展示内容

- 模块标题：样本列表。
- 说明：按系统当前顺序处理，点击任一项继续填写。
- 总数：使用接口返回的 `total`。
- 模块标题和总数使用常规字重，避免过度强调。
- 样本序号。
- 样本名称或编码。
- 问题状态。
- 问题数量或问题摘要。

### 5.2 布局与分页

- 默认每页 30 条。
- 每行 5 条。
- 使用服务端分页。
- 页码切换后保留任务详情顶部和记录区域状态。
- 大数据量不能一次性渲染所有样本。
- 窄屏下允许降为更少列数，但不能出现横向内容截断。

### 5.3 问题样本交互

- 普通样本使用默认样式。
- 必须修改样本使用红色样式。
- 建议修改样本使用黄色样式。
- 悬停问题样本展示批注面板。
- 批注面板包含样本名称、问题数量、对象名称、批注内容、处理类型和定位信息。
- 批注面板按问题逐条展示对象名称、处理等级、批注内容和 Frame 定位，顶部显示样本名称和问题总数。
- 点击样本进入工作台并定位。
- 样本卡片与悬浮批注面板封装为页面专属组件，由样本列表和质检记录共同复用。

## 六、规则校验记录

展示区域约占详情下方 70% 宽度。

字段：

- 校验/提交时间。
- 规则 ID、规则名称、规则版本。
- 规则详细内容。
- 命中样本。
- 证据对象。

规则：

- 按时间倒序，最新在上。
- 同一提交时间归为一条记录。
- 同一条规则允许多个命中样本和证据对象。
- 首次提交前展示规则校验空态。
- 数据为空时不得使用前端虚构的规则记录填充页面。
- 模块标题使用常规字重。

## 七、质检记录

展示区域约占详情下方 30% 宽度。

字段：

- 质检时间。
- 提交人。
- 质检人。
- 质检结果：通过、未通过。
- 问题样本。
- 问题严重程度。
- 问题样本悬浮详情中的批注和定位信息。

规则：

- 按质检时间倒序，最新在上。
- 无记录时展示“暂无记录”。
- 问题样本区分必须修改和建议修改。
- 问题样本使用缩略样本卡片展示样本名称，并保留与样本列表一致的悬浮详情。
- 质检时间、提交人、质检人和质检结果保持同一行展示，不换行。
- 质检记录列表不单独展示记录级提示文案，问题说明通过问题样本悬浮详情查看。
- 最新一条质检记录中的问题样本可进入工作台。
- 前端不根据任务状态主动隐藏接口返回的质检记录。
- 模块标题使用常规字重。

## 八、接口任务书

接口文档未发布前，以下为前端 API 层边界；真实 URL、统一响应结构和字段名称以接口文档为准。

### 8.1 任务列表

```http
GET /annotation-tasks
```

建议参数：

```ts
{
  aggregateStatus?: "annotating" | "qualityChecking" | "reworking" | "completed";
  keyword?: string;
  page: number;
  pageSize: number;
}
```

建议返回：

```ts
{
  list: AnnotationTaskListItem[];
  total: number;
  page: number;
  pageSize: number;
  statistics: {
    annotating: number;
    qualityChecking: number;
    reworking: number;
    completed: number;
  };
}
```

### 8.2 任务详情

```http
GET /annotation-tasks/{taskId}
```

返回任务顶部信息、具体状态、聚合状态、复核标签范围和任务样本 `itemId`；工作台地址不由该接口返回。

### 8.3 样本数据

任务详情接口的 `samples` 字段直接返回任务样本及最新规则问题，不再单独请求样本列表接口。

### 8.4 规则校验记录

```http
GET /annotation-tasks/{taskId}/rule-check-records
```

支持 `recordId`、`itemId`、`pageNo` 和 `pageSize` 查询参数。

### 8.5 人工质检记录

```http
GET /annotation-tasks/{taskId}/quality-records
```

支持 `submissionId`、`itemId`、`issueLevel`、`pageNo` 和 `pageSize` 查询参数。

### 8.6 重新指派

```http
POST /annotation-tasks/{taskId}/assign
```

请求体为 `{ annotatorId: number }`，成功时 `data` 为 `null`。

### 8.7 标签配置

```http
GET /annotation-tasks/{taskId}/label-config
```

返回任务标签、属性配置和工作台工具绑定信息，供标注工作台加载动态表单。

### 8.8 OHIF 影像标识

```http
GET /annotation-tasks/ohif/{itemId}
```

按样本 `itemId` 返回 `{ studyInstanceUID: string }`，供 CT 工作台拼接 `StudyInstanceUIDs`。

### 8.9 提交质检

```http
POST /annotation-tasks/{taskId}/submit-quality
```

提交后由后端执行规则质检并编排质检任务，返回规则校验记录及质检任务信息。

## 十一、测试与验收清单

### API 和纯函数

- 列表参数包含状态、关键词、页码和页大小。
- 复核中归入标注中统计和筛选。
- 列表分页结果和统计字段正确传递。
- 样本页大小固定默认为 30。
- 三个动作分别调用对应 API，不串用接口。
- API 层不把内部 Mock 数组暴露给页面。

### 路由

- `/annotation-task` 可通过菜单进入。
- `/annotation-task/:id` 可直接访问并加载真实详情页面。
- 详情页仍高亮标注任务菜单。
- 未登录访问受保护路由仍跳转登录页。

### 页面

- 搜索、Tab、分页均可用。
- 列表和详情加载、空态、失败状态明确。
- 样本每页 30 条，每行 5 条。
- 标签配置来自 `/annotation-tasks/{id}/label-config`，仅供标注工作台加载动态表单，详情页不展示；标注员工作台入口为 `/tool/pc/?taskId=<任务ID>&clipId=<样本itemId>[&mode=qc|re|readonly]`，仅在质检中、返修中、已完成状态追加对应模式，地址基于 `VITE_PC_TOOL_URL` 配置生成，不按标题推导且不使用固定 ID。CT 工作台使用 `GET /annotation-tasks/ohif/{itemId}` 返回的 `studyInstanceUID`。
- 人工质检记录不因前端状态判断被擅自隐藏。
- 点击流程动作先确认，取消不请求，确认只请求一次。
- 请求期间按钮禁用，成功后刷新数据。
- 业务显示值均来自 API、视图模型或格式化函数，不保留原型静态业务数字。
